# HTTP-адаптер 1С: kyvirok-bridge/1

**Статус:** клиент реализован в `bridge.mjs`. Это контракт для разработки серверного адаптера под конкретную базу. В поставке нет готового `.cfe`, серверной БСП-печати, криптоподписи или реализации трёх операторских API. Имитатор в тестах не является рабочим сервисом. До установки адаптера печать и ЭДО недоступны.

## Три сменных профиля

| ID | Основа адаптера | Проверка перед включением |
| --- | --- | --- |
| `1c-edo` | API установленной Библиотеки электронных документов | Версия БЭД, учётная запись организации, регламент контрагента, формат и подпись |
| `diadok` | API установленного модуля либо официальный API Диадока | Версия, авторизация, BoxId обеих сторон, XML, подпись и ID сообщения |
| `sbis` | API модуля СБИС либо Saby | Версия, профиль организации, адресат, маршрут подписи и отправки, ID документа |

Реализации имеют одинаковые операции prepare/sign/send/status; клиент не меняется при выборе другого реализованного профиля. Неподключённые возможности не публикуются как доступные. Встроенный 1С-ЭДО может работать через роуминг: профиль не определяется по оператору контрагента. Старые отправления сохраняют прежний профиль и ID; смена профиля не переносит сертификаты, ящики и историю.

Официальные отправные точки: [API БЭД](https://its.1c.ru/db/bed1101doc), [API Диадока](https://developer.kontur.ru/doc/diadoc-api/), [API Saby](https://saby.ru/help/integration/api), [штатная печать БСП](https://its.1c.ru/db/bsp3112doc/content/3036/hdoc). Методы и экспортные процедуры выбираются после получения точных версий. Самодельный приблизительный бланк не заменяет штатную УПД, сохранённый XML не доказывает отправку.

## Транспорт

Корень, например: `https://onec.example.lan/demo/hs/kyvirok/v1/`. Тот же origin и публикация, что у OData; Basic-auth текущей учётной записью 1С, её роли и RLS. Не включать привилегированный режим или `ОбменДанными.Загрузка` для обхода проверок.

JSON UTF-8; UTC ISO 8601. Тайм-аут 30 секунд, JSON до 200 КБ, полный предпросмотр до 24 КБ. Большая операция возвращает `queued` и выполняется контролируемым фоновым заданием. POST не повторяется автоматически. Редиректы не разрешены. Не выдавать SQL/BSL/команды ОС или произвольный вызов процедур от агента.

## GET capabilities

```json
{
  "protocol": "kyvirok-bridge/1",
  "configuration": {"name": "Бухгалтерия предприятия", "version": "точный релиз"},
  "operations": [{
    "name": "print.document", "title": "Штатная печатная форма", "kind": "print", "available": true,
    "inputSchema": {
      "type": "object", "properties": {"documentId": {"type": "string"}, "printCommand": {"type": "string"}},
      "required": ["documentId", "printCommand"], "additionalProperties": false
    }
  }]
}
```

`kind`: `print`, `report`, `draft`, `mutate`, `edo_prepare`, `edo_sign`, `edo_send`, `edo_status`. Для ЭДО добавить `providers`, например `["diadok"]`. При `available:false` можно указать `reason`. `edo.prepare/sign/send/status` должны соответствовать одноимённым kind с подчёркиванием. Сервер обязан валидировать `inputSchema`, права и бизнес-условия; клиент передаёт схему агенту, но не заменяет серверную проверку. Локальный `bridge-policy.json` дополнительно ограничивает операции поимённо.

## POST plans: предпросмотр

Запрос: `{operation, provider?, parameters, requestHash}`. SHA-256 рассчитывается по каноническому JSON `{operation, provider?, parameters}`: UTF-8, сортировка ключей объектов, сохранение порядка массивов, без пробелов (см. `stableJSON/hashRequest`). Отсутствующий provider не заменять null. Не передавать секреты в параметрах.

Эндпоинт не создаёт и не изменяет бизнес-документы, не проводит, не подписывает и не отправляет. Можно сохранить только внутренний план и неизменяемые файлы предпросмотра. Если штатный API не позволяет чистую подготовку, операция остаётся недоступной до реализации такого режима.

```json
{
  "planId": "e653f2d7-8a8e-4611-a839-c51aa596822f", "requestHash": "64 hex-символа",
  "expiresAt": "2026-11-20T12:05:00.000Z",
  "review": {
    "title": "Печать УПД № 25", "effects": ["Сформировать PDF, не проводить и не отправлять"],
    "changes": [], "sourceVersions": {"ключ документа": "версия"},
    "details": {"number": "25", "total": "6283.49", "currency": "RUB"}, "files": []
  }
}
```

Заглушки хешей в примерах заменить реальными строчными hex SHA-256. `changes` содержит полный набор изменяемых объектов/полей и значения «было/станет»; `effects` — все связанные действия. План привязан к пользователю, публикации, организации, операции, параметрам и версиям. UUID одноразовый, срок до пяти минут. Любое изменение источника, получателя, подписи или файла требует нового плана.

Для ЭДО обязательно добавить в review:

```json
{
  "edo": {
    "provider": "diadok",
    "sender": {"id": "org", "name": "Отправитель", "inn": "0000000000"},
    "recipient": {"id": "buyer", "name": "Получатель", "inn": "1111111111", "kpp": "111111111"},
    "senderBoxId": "ящик отправителя", "recipientBoxId": "ящик получателя",
    "documents": [{
      "id": "документ", "number": "25", "date": "2026-11-20", "total": "6283.49", "currency": "RUB",
      "files": [{"id": "e653f2d7-8a8e-4611-a839-c51aa596822f", "name": "UPD.xml",
        "mimeType": "application/xml", "size": 1234, "sha256": "64 hex-символа"}]
    }],
    "signature": {"required": true, "state": "signed", "certificateThumbprint": "отпечаток",
      "signer": "Владелец сертификата", "powerOfAttorney": "ID МЧД, если применимо"}
  }
}
```

ИНН — 10/12 цифр, суммы строкой без округления JavaScript. Для подписи state `not_signed`, для отправки — `signed`. Отправка не должна скрыто подписывать. Штатный криптомеханизм проверяет подпись именно показанных файлов, сертификат и полномочия. Закрытый ключ и PIN не покидают штатное хранилище.

## POST plans/{planId}/execute

Запрос содержит только `{requestHash, reviewHash}`. Второй хеш — канонический SHA-256 объекта review. Клиент отправляет execute один раз после формы с `confirm:true`; параметры в execute не редактируются.

Обязанности сервера:

1. Повторно проверить пользователя, права, настройки, TTL и оба хеша.
2. Атомарно захватить план; второй/параллельный вызов не исполняет его снова.
3. В транзакции 1С заблокировать затрагиваемые объекты, перечитать их версии. При конфликте ничего не менять.
4. Выполнить ровно согласованное штатными API. Создание, проведение, подпись, отправка — отдельные планы.
5. Для внешних запросов хранить постоянный журнал `pending/sending/sent/unknown`, ID плана/оператора и хеши. Транзакция 1С не делает HTTP-отправку атомарной: при неоднозначном ответе сначала сверить операторский статус. Если API поддерживает идемпотентный ключ, использовать ключ плана.
6. Прочитать результат и сохранить квитанцию. HTTP 200 не равен доставке контрагенту.

Execute и status возвращают:

```json
{
  "planId": "e653f2d7-8a8e-4611-a839-c51aa596822f", "requestHash": "64 hex-символа",
  "state": "completed", "message": "Форма сформирована", "receiptId": "устойчивый ID результата",
  "verification": {"sourceUnchanged": true}, "files": []
}
```

Состояния: `completed`, `queued`, `rejected`, `unknown`. В verification только фактически проверенные сведения/операторские статусы. Нельзя заменять адресата или файл под прежним подтверждением.

## GET plans/{planId}/status и GET files/{id}

Status только читает журнал, не отправляет и не подписывает повторно. Доступ владельцу или явно уполномоченному пользователю. Журнал переживает перезапуск сервера. Клиент хранит последние 100 исполненных планов в памяти; после перезапуска клиента проверяйте planId в 1С.

Files возвращает неизменяемые байты, доступные текущему пользователю; внешние URL не поддерживаются. MIME: PDF, XML, CSV, XLSX, `application/pkcs7-signature`. Манифест файла одинаков везде: UUID id, name, mimeType, size, sha256. Клиент сверяет размер/SHA-256 и сохраняет файл под случайным именем; неверный файл не выдаётся. Максимум 20 МБ на файл.

## Приёмка

На копии базы и тестовом маршруте оператора проверить: отмена формы без изменений; TTL; чужое изменение документа; смена адресата/сертификата/файла; два одновременных execute; отзыв прав; авария после фактической отправки до ответа; статус после перезапуска; корректность штатной печатной формы; настоящая квитанция. Локальные тесты клиента не заменяют проверки серверной части и реальных операторов.

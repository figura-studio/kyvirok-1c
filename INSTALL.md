# Подключить kyvirok for 1C

> Для **0.2.0-preview.3** начните с [задания агенту сотрудника](AGENT-GUIDE.md). Установка ниже подключает OData. Отдельный Диадок может работать без расширения 1С: [API, импорт XML в черновик и браузерный путь](EXTERNAL-EDO.md). Автоматическая генерация XML из OData, подпись и отправка не реализованы.

Для подключения нужны настольный Codex или другой локальный MCP-клиент, Node.js 24.18 или новее и доступ к опубликованной базе 1С 8 через OData. Для записи клиенту нужна поддержка форм подтверждения. В ZIP уже есть собранный сервер. Доступ к базе настраивается на компьютере, где будет запускаться коннектор. Из дома используйте корпоративный VPN или запускайте Codex и коннектор на рабочем компьютере внутри сети через разрешённый удалённый рабочий стол.

## 1. Администратор 1С готовит базу

Если OData уже опубликован, используйте адрес, который передал администратор. В «Бухгалтерии предприятия 3.0» откройте **Администрирование → Синхронизация данных → Настройки стандартного интерфейса OData → Состав**. Разверните «Документы» и отметьте виды документов для задачи. Например, для чтения отгрузки выберите «Реализация товаров и услуг», если в вашей конфигурации используется это название. Связанные справочники нужны, когда требуется читать их данные, например названия покупателей или товаров. Сохраните уже выбранные объекты и нажмите «Сохранить и закрыть». За состав публикации отвечает администратор базы. У пользователя отдельно должны быть разрешены вход через OData и чтение выбранных объектов. [Настройки и права OData в 1С](https://1cfresh.com/articles/data_odata)

Пример внутреннего адреса — `http://onec.example.lan/demo/odata/standard.odata/`. Установщик принимает обычный HTTP для имён, которые на рабочем компьютере разрешаются в частные, локальные или loopback-адреса. Перед вводом пароля он проверяет адрес без учётных данных. При перенаправлении на HTTPS того же имени и пути он сохраняет HTTPS. При смене имени или пути используйте конечный адрес OData, подтверждённый администратором. При прямом HTTP трафик с учётными данными и содержимым документов передаётся без шифрования на участке HTTP; такой адрес используйте только в доверенной сети компании.

## 2. Один раз настроить компьютер для теста

Скачайте ZIP со страницы проекта, распакуйте и откройте PowerShell в папке с этим файлом. На Windows запустите:

```powershell
node --version
.\setup-windows.ps1
```

Укажите имя подключения (например, `demo`), адрес OData, свой логин, часовой пояс базы и пароль в закрытом вводе. Настройки сохраняются в `%APPDATA%\kyvirok-1c`; пароль защищён Windows DPAPI и читается под тем же пользователем Windows. Если организация ограничивает запуск PowerShell-скриптов, настройку выполняет её администратор.

Чтобы разрешить пробную запись, администратор копирует `write-policy.example.json` из ZIP в эту личную папку под именем `write-policy.json`, сверяет имя подключения и точные имена объектов и полей с метаданными базы. В примере используется вымышленное подключение `demo`: замените его своим именем. Разрешайте сначала одно поле, например комментарий к черновику. Поля для создания и изменения задаются раздельно. Отсутствие правил оставляет доступ на чтение.

**После любого изменения правил перезапустите MCP-сервер и создайте новый предпросмотр.** Правила загружаются при запуске. Если файл изменился, появился или исчез во время работы, запись блокируется до перезапуска; уже открытая форма не обходит эту проверку.

Проверьте конфигурацию без обращения к 1С и без чтения пароля:

```powershell
node .\plugins\kyvirok-1c\server.mjs --diagnose
```

В ответе будут версия, полный `path`, признак `loaded`, разрешения `permissions` и `writeEnabled`. В действующем чате вызовите **`get_write_policy`**: он также показывает `changedSinceStart` и `restartRequired` именно для работающего процесса. Если путь переопределён через `KYVIROK_1C_POLICY`, используется этот абсолютный путь. Для нестандартной папки настроек задайте тот же `ONEC_MCP_DATA_DIR`, что и в настройках MCP-сервера.

Для создания реализации нужны отдельные разрешения `create` на её фактическое имя из `list_entities` и поля из `describe_entity`. Например, фрагмент правил может выглядеть так:

```json
{
  "demo": {
    "Catalog_Номенклатура": { "create": ["Description"] },
    "Document_РеализацияТоваровУслуг": {
      "create": ["Date", "Организация_Key", "Контрагент_Key", "ДоговорКонтрагента_Key", "Склад_Key", "Комментарий", "Товары"]
    }
  }
}
```

Это пример структуры, а не готовые правила для любой конфигурации. Проверьте обязательные реквизиты, строки и суммы в вашей 1С. `create` не даёт права `update`. Разрешение поля `Товары` позволяет передать всю таблицу; при изменении таблица заменяется целиком. Поля `Posted`, `DeletionMark`, `Ref_Key` и `DataVersion` не разрешаются коннектором даже при наличии в файле правил.

## 3. Подключить к Codex

**Для одного тестировщика с ZIP.** В той же папке выполните:

```powershell
$server = (Resolve-Path '.\plugins\kyvirok-1c\server.mjs').Path
codex mcp add kyvirok-1c -- node $server
```

Если команда `codex` недоступна, откройте в настольном приложении **Settings → MCP servers → Add server**. Выберите STDIO, имя `kyvirok-1c`, команду `node` и передайте полный путь к распакованному `plugins/kyvirok-1c/server.mjs` одним аргументом. Сохраните настройки и перезапустите сервер. Если такая запись уже есть, проверьте путь и обновите существующую запись. [Подключение MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp)

В новом чате вызовите `list_connections` и затем `list_entities` для своего подключения. Первый вызов показывает локальные настройки, второй проверяет доступ к метаданным 1С. Для проверки документов запросите одну существующую реализацию через `query`, указав только номер и дату. Пустой результат при успешном запросе тоже возможен. Проверку записи с подтверждением проводите отдельно на тестовой копии.

## Подтверждение и разбор ошибок

Перед записью агент вызывает `preview_change`, показывает покупателя (или ключ, который нужно сверить), дату, строки, количество, суммы, НДС и полный список передаваемых полей. Неуказанные суммы и реквизиты не рассчитываются коннектором: их нужно проверить по правилам своей 1С. В `apply_reviewed_change` менеджер устанавливает галочку **«Записать именно эти изменения в 1С»** и принимает форму. Одного нажатия «Принять» без галочки недостаточно. После успеха коннектор заново читает объект: сверяет переданные значения и для документа проверяет `Posted = false`. Ответ `verification.state = differences` требует проверки отличий, а `unavailable` означает, что запись подтверждена, но контрольное чтение не удалось. Оба случая не являются разрешением повторить создание.

| Результат | Что проверить |
| --- | --- |
| `reason: decline` | Клиент вернул отказ. Это может быть нажатие человека или автоматическое отклонение; сервер не может их различить. |
| `reason: cancel` | Клиент сообщил, что форму закрыли. |
| `reason: unchecked` | Форма принята, но `confirm` не равен `true`. Нужен новый предпросмотр и установленная галочка. |
| `reason: unsupported` | Клиент не объявил поддержку формы MCP elicitation. |
| `reason: error` | Форма не вернула корректное подтверждение, например из-за ошибки связи с клиентом. |
| `restartRequired: true` | Перезапустите MCP-сервер после изменения правил и подготовьте новый предпросмотр. |
| Результат записи не подтверждён | Проверьте наличие объекта в 1С: запрос мог выполниться до обрыва связи. Автоповтора записи нет. |

Если форма вообще не появляется, проверьте **активный режим текущего чата**, выбранный профиль и действующие ограничения рабочего пространства. Настройка в другом профиле сама по себе не меняет текущий чат. Для Codex с гранулярными разрешениями категория `approval_policy.granular.mcp_elicitations` должна быть `true`, чтобы формы могли показываться. Если категория отключена, клиент может автоматически вернуть `decline`. Меняйте только эту категорию в существующей конфигурации, сохраняя остальные параметры: не заменяйте весь `approval_policy` готовым обрывком. Если режим или политика организации запрещает формы, выберите разрешённый интерактивный режим либо обратитесь к администратору. [Справочник настроек Codex](https://learn.chatgpt.com/docs/config-file/config-reference#approval_policy)

Задание агенту после установки:

> Проверь версию kyvirok-1c (для этой предварительной сборки — 0.2.0-preview.1), вызови get_write_policy и покажи путь и разрешения. Если меняли файл правил, перезапусти MCP-сервер. Проверь метаданные, обязательные реквизиты и доступные права. Перед записью покажи мне покупателя, дату, строки, количества, суммы, НДС и состояние проведения. Получи подтверждение через форму с галочкой. Если форма не появилась, проверь действующий режим чата и разрешение MCP elicitation, сохраняя остальные настройки. После записи проверь результат повторного чтения и Posted=false. При неизвестном результате записи сначала найди объект в 1С, не повторяй создание автоматически.

## Другие платформы и разработка

На Linux/macOS администратор задаёт абсолютный `ONEC_MCP_DATA_DIR` в окружении сервера. В этом каталоге создают личный `config.json` по схеме ниже и при необходимости `write-policy.json`. Для пароля подключения `demo` передайте процессу `ONEC_DEMO_PASSWORD` через локальный менеджер секретов. Используйте отдельный приватный каталог. Этот способ также работает на Windows. Пример намеренно содержит демонстрационные значения.

```json
{"connections":{"demo":{"baseUrl":"https://onec.example.invalid/demo/odata/standard.odata","login":"test-manager","serverTimezone":"Europe/Moscow"}}}
```

Точка запуска — `node plugins/kyvirok-1c/server.mjs`. Это stdio-сервер, который запускает MCP-клиент. Подключение не публикует базу в интернете. Выбранные для ответа данные попадают в используемый вами ИИ-клиент, поэтому состав доступных объектов согласуйте с владельцем базы. Если нет подтверждения ответа 1С после ошибки связи, проверьте результат в базе перед повторной попыткой.

Для сборки из исходников установите Node.js и pnpm 11, затем выполните:

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm test
```

Для полного ZIP на Windows после успешных сборки и тестов выполните `pnpm package:windows`. Получатся `dist/kyvirok-1c-0.2.0-preview.1.zip` и файл SHA-256. Упаковщик использует список публичных файлов и проверяет обязательные компоненты, включая пример правил. В ZIP входят исходники для команд `build` и `test`; готовый сервер запускается без установки зависимостей. Для разработки после распаковки сначала выполните установку зависимостей и сборку из блока выше.

Исходники изменений — `changes.mjs`, регистрация MCP-инструментов — `server.mjs`, диагностика правил — `policy.mjs`, зависимости исходного проекта 1c-odata — `vendor/`. Конфигурация распространяемого каталога находится в `.agents/plugins/marketplace.json`.

# Подключить kyvirok for 1C

Для подключения нужны настольный Codex или другой локальный MCP-клиент, Node.js 24.18 или новее и доступ к опубликованной базе 1С 8 через OData. Для записи клиенту нужна поддержка форм подтверждения. В ZIP уже есть собранный сервер. Доступ к базе настраивается на компьютере, где будет запускаться коннектор. Из дома используйте корпоративный VPN или запускайте Codex и коннектор на рабочем компьютере внутри сети через разрешённый удалённый рабочий стол.

## 1. Администратор 1С готовит базу

Если OData уже опубликован, используйте адрес, который передал администратор. В «Бухгалтерии предприятия 3.0» откройте **Администрирование → Синхронизация данных → Настройки стандартного интерфейса OData → Состав**. Разверните «Документы» и отметьте виды документов для задачи. Например, для чтения отгрузки выберите «Реализация товаров и услуг», если в вашей конфигурации используется это название. Связанные справочники нужны, когда требуется читать их данные, например названия покупателей или товаров. Сохраните уже выбранные объекты и нажмите «Сохранить и закрыть». За состав публикации отвечает администратор базы. У пользователя отдельно должны быть разрешены вход через OData и чтение выбранных объектов. [Настройки и права OData в 1С](https://1cfresh.com/articles/data_odata)

Пример внутреннего адреса — `http://onec.example.lan/demo/odata/standard.odata/`. Установщик принимает обычный HTTP для имён, которые на рабочем компьютере разрешаются в частные, локальные или loopback-адреса. Перед вводом пароля он проверяет адрес без учётных данных. При перенаправлении на HTTPS того же имени и пути он сохраняет HTTPS. При смене имени или пути используйте конечный адрес OData, подтверждённый администратором. При прямом HTTP трафик с учётными данными и содержимым документов передаётся без шифрования на участке HTTP; такой адрес используйте только в доверенной сети компании.

## 2. Один раз настроить компьютер для теста

Скачайте ZIP со страницы проекта, распакуйте и откройте PowerShell в папке с этим файлом. На Windows запустите:

```powershell
node --version
.\setup-windows.ps1
```

Укажите имя подключения (например, `demo`), адрес OData, свой логин, часовой пояс базы и пароль в закрытом вводе. Настройки сохраняются в `%APPDATA%\kyvirok-1c`; пароль защищён Windows DPAPI и читается под тем же пользователем Windows. Если организация ограничивает запуск PowerShell-скриптов, настройку выполняет её администратор.

Чтобы разрешить пробную запись, администратор копирует `write-policy.example.json` в эту личную папку под именем `write-policy.json`, сверяет имя подключения и точные имена объектов и полей с метаданными базы. Разрешайте сначала одно поле, например комментарий к черновику. Поля для создания и изменения задаются раздельно. Отсутствие правил оставляет доступ на чтение. После изменения правил перезапустите MCP-сервер.

## 3. Подключить к Codex

**Для одного тестировщика с ZIP.** В той же папке выполните:

```powershell
$server = (Resolve-Path '.\plugins\kyvirok-1c\server.mjs').Path
codex mcp add kyvirok-1c -- node $server
```

Если команда `codex` недоступна, откройте в настольном приложении **Settings → MCP servers → Add server**. Выберите STDIO, имя `kyvirok-1c`, команду `node` и передайте полный путь к распакованному `plugins/kyvirok-1c/server.mjs` одним аргументом. Сохраните настройки и перезапустите сервер. Если такая запись уже есть, проверьте путь и обновите существующую запись. [Подключение MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp)

В новом чате вызовите `list_connections` и затем `list_entities` для своего подключения. Первый вызов показывает локальные настройки, второй проверяет доступ к метаданным 1С. Для проверки документов запросите одну существующую реализацию через `query`, указав только номер и дату. Пустой результат при успешном запросе тоже возможен. Проверку записи с подтверждением проводите отдельно на тестовой копии.

## Другие платформы и разработка

На Linux/macOS администратор задаёт абсолютный `ONEC_MCP_DATA_DIR` в окружении сервера. В этом каталоге создают личный `config.json` по схеме ниже и при необходимости `write-policy.json`. Для пароля подключения `demo` передайте процессу `ONEC_DEMO_PASSWORD` через локальный менеджер секретов. Используйте отдельный приватный каталог. Этот способ также работает на Windows. Пример намеренно содержит демонстрационные значения.

```json
{"connections":{"demo":{"baseUrl":"https://onec.example.invalid/demo/odata/standard.odata","login":"test-manager","serverTimezone":"Europe/Moscow"}}}
```

Точка запуска — `node plugins/kyvirok-1c/server.mjs`. Это stdio-сервер, который запускает MCP-клиент. Подключение не публикует базу в интернете. Выбранные для ответа данные попадают в используемый вами ИИ-клиент, поэтому состав доступных объектов согласуйте с владельцем базы. Если нет подтверждения ответа 1С после ошибки связи, проверьте результат в базе перед повторной попыткой.

Для сборки из исходников установите Node.js и pnpm 11, затем выполните:

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm test
```

Исходники изменений — `changes.mjs`, регистрация MCP-инструментов — `server.mjs`, зависимости исходного проекта 1c-odata — `vendor/`. Конфигурация распространяемого каталога находится в `.agents/plugins/marketplace.json`.
